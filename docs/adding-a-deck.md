# 新しいデッキを追加する

アプリは `src/data/decks/` にあるデッキを自動で一覧に出す。デッキを1つ足すのに必要なのは、
`decks/<id>/` に元データを置いて取り込むことだけで、**アプリのコードを書き換える必要はない。**
足したデッキは上部の「デッキ」の選択肢に出て、`?deck=<id>` で直接開ける。

所要時間の目安：カードの並べと取り込みで15分、日本語の確認とコツ書きで1〜2時間（カード80種なら）。

## 0. 全体の流れ

```
npm run new-deck -- <id> "<表示名>" "<統率者の英語名>"   … decks/<id>/ に雛形ができる
decks/<id>/cards.csv にカードを並べる                     … スプレッドシートの書き出しでもよい
npm run import-deck -- <id>                               … src/data/decks/<id>.json ができる
decks/<id>/ja.json を直し、コツを書く → もう一度 import-deck
（必要なら）カードの自動処理を書く → テスト → PR
```

## 1. 雛形を作る

```bash
npm run new-deck -- krenko "クレンコ・ゴブリン" "Krenko, Mob Boss"
```

- **ID**（`krenko`）：`decks/` のフォルダ名・`src/data/decks/<id>.json`・URL の `?deck=` に使う。ASCII の kebab-case
- **表示名**：デッキの選択肢と一覧に出る。**日本語で書く**（画面に英語を出さない約束。CONTRIBUTING 4.4）
- **統率者**：Scryfall の英語名（正式名）。共闘などで2人いるときは続けて書く

```bash
npm run new-deck -- <id> "<表示名>" "<1人目の統率者の英語名>" "<2人目の統率者の英語名>"
```

できるファイル：

| ファイル | 中身 |
|---|---|
| `decks/<id>/config.json` | `name`（表示名）・`csv`（カードの一覧のファイル名）・`commanders`・`include` |
| `decks/<id>/cards.csv` | カードの一覧。最初は統率者の行だけ |
| `decks/<id>/ja.json` | 日本語のタイプ行・効果・使い方のコツ。最初は空 |

## 2. カードを並べる（cards.csv）

列は `投入済み,和名,英語名`。1行1枚で、同じカードは枚数ぶん行を並べる（基本土地なら山を15行）。

```csv
投入済み,和名,英語名
TRUE,,"Krenko, Mob Boss"
TRUE,山,Mountain
TRUE,山,Mountain
TRUE,衝撃の震え,Impact Tremors
FALSE,,Goblin Assault
```

- **英語名**は Scryfall の正式名にする（カンマを含むなら `"` で囲む）。両面・出来事・部屋は表面の名前でよい
- **和名**は空でよい（日本語の名前は `ja.json` の `name` か、取り込み時の日本語版から決まる）
- **投入済み**：`config.json` の `include` が `all` なら全行を使い、`inDeck` なら `TRUE` の行だけを使う。
  「買う予定のカードも含めたレシピ全体」と「手元にあるカードだけ」を切り替えたいときに使う
- 統率者の行も入れる（統率者込みで100枚にする）

### スプレッドシートから書き出す場合

Ingris のデッキと同じ形のスプレッドシート（`投入済み,和名,英語名,…` の列を持つ「デッキリスト」シート）なら、
CSV で書き出したファイルをそのまま `decks/<id>/` に置き、`config.json` の `csv` をそのファイル名にする。
ほかの列（マナコスト・備考など）は読まないので残っていてよい。

## 3. 取り込む

```bash
npm run import-deck -- krenko
```

Scryfall から英語の正文・タイプ・画像を、日本語版の印刷から日本語の文章と画像を取ってきて、
`src/data/decks/krenko.json` を作る。80種で1〜2分かかる（Scryfall の検索はアクセスが続くと制限されるので、
スクリプトが待って取り直す。止まって見えても待つ）。

出力の読み方：

| 出力 | 意味・やること |
|---|---|
| `[krenko] 81 種 / 100 枚（統率者込み）…` | 書き出した。100枚でなければ「注意」が出る |
| `Scryfall に無いカード: …` | 英語名の綴りが違う。cards.csv を直してやり直す |
| `統率者がデッキにありません` | config.json の `commanders` と cards.csv の英語名が一致していない |
| `ほかのデッキからタイプ行・効果を写した` | 既存デッキで日本語を整えたカード。**コツだけ書く** |
| `日本語版から下書きを足した` | 新しいカード。**日本語を確認して直し、コツを書く**（次節） |
| `日本語版の画像が無く英語版の画像を使う` | 日本語版が出ていないカード。そのままでよい |

## 4. 日本語を確認し、コツを書く（ja.json）

下書きは Scryfall の日本語データから作るが、**そのままでは使えないことが多い**。1件ずつ確認する。

例（`decks/ingris/ja.json` から）：

```json
"Impact Tremors": {
  "type": "エンチャント",
  "text": "クリーチャー１体があなたのコントロール下で戦場に出るたび、衝撃の震えは各対戦相手にそれぞれ１点のダメージを与える。",
  "tip": "トークンを出すカードより先に置く。赤の発生源なのでトーブラン・機械化戦の両方が乗る"
}
```

| 項目 | 直すこと |
|---|---|
| キー | Scryfall の正式名（出来事・部屋は `A // B`）。取り込みが付けるので触らない |
| `name` | 和名を上書きしたいときだけ。cards.csv の和名が空で日本語版も無いカードは英語名のままになるので、ここで日本語にする |
| `type` | 日本語のタイプ行。空・英語のままのことがある |
| `text` | 日本語の効果。次の崩れを直す：英語のまま（新しいカード・基本土地）／記号の崩れ（`{(}b/r)}` → `{B/R}`、`{4BBB}` → `{4}{B}{B}{B}`）／ふりがなの残り（`虚（きょ）空（くう）`）／部屋・出来事の片面の欠け |
| `tip` | 使い方のコツ（下記）。基本土地など書くことが無ければ空文字 |

### コツの書き方

- このデッキでどう使うと得か（何と組み合わせると何点・何枚になるか、いつ出すか）を1〜3文で
- **カード名は日本語で書く**（英語名を混ぜない）
- 効果の言い換えは書かない（効果は `text` にある）
- アプリが近似で処理するものは「このアプリでは〜とみなす」と書く
- コツは**デッキごと**。同じカードでもデッキが違えば書き直してよい（`text` と `type` はデッキ間で写される）

直したら、もう一度 `npm run import-deck -- <id>` を流して `src/data/decks/<id>.json` に反映する。

## 5. 動かして確かめる

```bash
npm run dev
```

`http://localhost:5173/?deck=<id>` を開く（または上部の「デッキ」で選ぶ）。

- 統率者が統率領域にいて、ライブラリーが 100 − 統率者の数 − 7 枚
- 「デッキ」パネルで枚数とマナ・カーブが合っている
- カード詳細の名前・タイプ行・効果・コツが日本語で、崩れていない
- 統率者の固有色で、統率の塔などが正しい色を出す（固有色は統率者の色から決まる）

## 6. カードの自動処理（必要なら）

**新しいデッキのカードは、自動処理を書かなくても遊べる。** スクリプトの無いカードは「効果は手動で処理」と出て、
編集モードで処理できる。既存デッキと同じカードは、そのデッキ用に書いた自動処理がそのまま効く。

勝ち筋に関わるカード（ダメージ・トークン・増幅・ドロー・マナ）を自動化するときは、
CONTRIBUTING の「4. エンジンの約束」と「5. カードの自動処理を足す」に従って `src/cards/scripts/` に書き、
e2e のテストを足してカバレッジ 100% を保つ。

統率者が絡む処理（「統率者をコントロールしているなら」など）は `isCommander(s, card)` を、
固有色は `identity(s)` を使う。どちらも遊んでいるデッキから決まるので、デッキ名や統率者名を直書きしない。

## 7. コミットと PR

1つの PR にまとめる：

- `decks/<id>/`（config.json・CSV・ja.json）
- `src/data/decks/<id>.json`（生成物。Pages のビルドで Scryfall に問い合わせないようにコミットする）
- 自動処理を書いたなら `src/cards/scripts/` とテスト

```bash
git checkout -b deck-<id>
npm run typecheck && npm test && npm run test:e2e
git add decks/<id> src/data/decks/<id>.json
git commit -m "<表示名> のデッキを足す"
git push -u origin deck-<id>
gh pr create
```

CI（型検査・ユニット・e2e とカバレッジ 100%）が通ればマージでき、マージすると Pages に配信される。

## 8. デッキを直す・消す

- **カードの入れ替え**：`cards.csv` を直して `npm run import-deck -- <id>`。抜いたカードの `ja.json` の項目は残っていても害は無い
- **表示名・統率者の変更**：`config.json` を直して取り込み直す
- **デッキを消す**：`decks/<id>/` と `src/data/decks/<id>.json` を消す。そのデッキの記録は、利用者の端末に残るが一覧には出なくなる
- **既定のデッキ**：一覧の先頭（`src/data/decks/` のファイル名順で最初のもの）が、初めて開いた人と知らない `?deck=` のときのデッキになる

## 9. しくみ（知っておくと迷わないこと）

- `src/engine/deck.ts` が `src/data/decks/*.json` を `import.meta.glob` で全部読み、
  カード名でまとめた**カード目録**を作る。ルールと表示に使うカードの情報はデッキに依らず目録から引く
- デッキごとに違うのは**統率者・枚数・コツ**だけ。統率者と遊んでいるデッキの ID は対局の状態（`GameState` の
  `commanders` / `deckId`）に入り、統率者税・統率者ダメージ・固有色はそこから決まる。コツは `tipOf(deckId, name)` で引く
- 同じ英語名のカードは、どのデッキでも同じ目録の項目になる（先に読んだデッキのものが使われる）。
  `text` や `type` を直すなら、そのカードを持つすべてのデッキの `ja.json` をそろえておく
- e2e とユニットテストのときだけ `tests/fixtures/decks/` のテスト用デッキが一覧に足される（`vite.config.ts` の `@extra-decks`）。
  本番の一覧には出ない
- 記録（キルターンの履歴）は利用者の端末の localStorage にデッキ ID 付きで残り、デッキごとに集計される
